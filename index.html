概念边界与图中简化
Harness 与 Agent
本图讨论基于 LLM 的 Agent。Harness 是使模型能够持续执行任务的运行支撑系统，不是额外的模型或流水线节点。框中展示其负责协调的模型接口、上下文、状态、执行控制；模型推理能力来自模型本身。外部工具、存储和子 Agent 不必归属于 Harness。
RAG 的两种接法
左侧是完整的独立 RAG：检索 → 增强 → 生成。与 Agent 结合时，证据经观察与状态更新进入 Agent 的 Context，由右侧模型继续生成或行动，不必再调用左侧独立生成器。不同路径共用底图，不代表所有节点都要执行。
检索编码
向量路径将 Query 编码后，与兼容表示空间中的文档向量匹配；编码器不一定是同一个。BM25 走关键词索引，不需稠密 Query Embedding。可只用一条路径，也可混合检索。Metadata 可用于过滤；重排可选。
State、Memory、Context
State 包含当前任务状态；短期记忆通常是其中的会话信息，可以持久化。Context 是本轮实际选入模型输入的信息。长期记忆跨会话保存，图中用读取路径表示；可按需写回。记忆不等于模型权重更新。
CoT 与 ReAct
CoT 是中间步骤推理方法，不等于多次模型调用的 Prompt Chaining。ReAct 是将推理、行动、观察交织的思路，是 Agent loop 的一种实现；不是每个 Agent 都必须使用。动画表示可观察的调用与信息流，不展示模型内部推理原文。
Orchestration 与 Router
Orchestration 是协调调用、状态、依赖与停止的职责。Router 负责选择路径，可由规则或模型实现，不必独立成服务。下方五种编排模式不属于 Subagent 的子类，也不是固定先后顺序。
Evaluator–Optimizer 与 Subagent
评估—修订可以用于局部输出或最终候选结果，不是参数训练，也不等于所有环境反馈循环。Subagent 是接受委派的执行角色，可以共享基础模型，并有自己的上下文、工具和循环；普通工作者不必是完整 Agent。
停止与安全边界
模型可以选择完成，Harness 也可按步数、预算、超时或权限规则停止、重试或请求人工介入。图为教学用职责划分，工程实现没有唯一统一的分层标准。
